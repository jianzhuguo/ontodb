# 2026-11-20

## BloomFilter insert 性能修复

- 文件：`crates/onto-storage/src/lsm/bloom_filter.rs`
- 问题：`hash(key, i)` 在每个 probe 都重新算一遍 FNV + Murmur，两个哈希又各自独立扫描 key。1% 假阳性率下 `num_hashes≈7`，一次 insert 扫 key 14 遍，lookup 同样。
- 修复：
  - 新增 `base_hashes()`，把 FNV-1a 和 murmur-style mixer 融合成一次遍历，两个哈希各算一次。
  - `insert` / `might_contain` 用累加 `hash = hash.wrapping_add(step)` 代替 `h1 + i*h2`（模 2^64 等价），省掉每次 probe 的乘法。
  - 新增私有 `bit_mask()` 统一算 word idx / bit mask。
  - 位图与旧实现逐位一致，磁盘上的 SST bloom 完全兼容。
- 回归测试（新增 2 个）：测试里保留旧算法作 oracle，多种 n / fp_rate 下断言 `to_bytes()` 完全一致；再对 2048 个 absent key 断言查询结果一致。
- 验证：`cargo test -p onto-storage --lib bloom` 6 passed；全量 `cargo test -p onto-storage --lib` 331 passed / 0 failed（原 329 + 2 新增），耗时 556s。
- 独立 rustc -O 基准（20 万 key、7 hash、24 字节 key）：旧 66.0 ms（3.0 M keys/s）→ 新 13.4 ms（14.9 M keys/s），约 4.9 倍。基准临时文件已删除。
