# SaaS平台案例：某CRM厂商多租户改造

## 客户背景

| 项目 | 说明 |
|------|------|
| 客户类型 | 某SaaS CRM厂商 |
| 项目规模 | 服务500家企业客户 |
| 数据规模 | 管理1亿条客户数据 |
| 核心需求 | 多租户隔离、数据安全、高性能 |

## 传统方案痛点

### 系统架构

```
原有方案：共享表+tenant_id
┌─────────────────────────────────────┐
│           MySQL单实例               │
│  ┌─────────────────────────────┐    │
│  │ customers表（所有租户）       │    │
│  │ id | tenant_id | name | ... │    │
│  └─────────────────────────────┘    │
│  ┌─────────────────────────────┐    │
│  │ orders表（所有租户）          │    │
│  │ id | tenant_id | amount | ..│    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

### 核心痛点

| 痛点 | 具体表现 |
|------|----------|
| 安全风险 | SQL注入可能泄露其他租户数据 |
| 性能问题 | 每次查询都需要过滤tenant_id |
| 索引效率 | 复合索引（tenant_id + 其他字段）效率低 |
| 数据隔离 | 依赖应用层，数据库层无隔离 |
| 运维困难 | 无法按租户备份、恢复、迁移 |

### 典型场景问题

**场景1：安全风险**
```python
# SQL注入风险
def get_customers(tenant_id, name):
    # 如果name = "' OR '1'='1"，会泄露所有租户数据
    query = f"SELECT * FROM customers WHERE tenant_id = '{tenant_id}' AND name = '{name}'"
    return db.execute(query)

# 传统方案无法在数据库层防止这种攻击
```

**场景2：性能问题**
```sql
-- 每次查询都需要过滤tenant_id
SELECT * FROM customers 
WHERE tenant_id = 'tenant_123' 
  AND status = 'active'
  AND created_at > '2026-01-01';

-- 问题：
-- 1. 索引效率低（需要复合索引）
-- 2. 扫描行数多（需要扫描所有租户数据）
-- 3. 查询延迟高（10-50ms）
```

## OntoDB解决方案

### 系统架构

```
OntoDB命名空间架构：
┌─────────────────────────────────────────────┐
│              OntoDB单实例                    │
│  ┌─────────────┐  ┌─────────────┐           │
│  │ 命名空间A   │  │ 命名空间B   │  ...      │
│  │ (租户A)     │  │ (租户B)     │           │
│  │ ┌─────────┐│  │ ┌─────────┐│           │
│  │ │customers││  │ │customers││           │
│  │ │orders   ││  │ │orders   ││           │
│  │ └─────────┘│  │ └─────────┘│           │
│  └─────────────┘  └─────────────┘           │
└─────────────────────────────────────────────┘
```

### 数据模型

```
命名空间：tenant_123

数据类型：
- 结构化记录：客户信息、订单数据
- 图结构：客户关系网络
- 向量索引：客户画像嵌入
- 时序数据：客户行为时间线
- 语义三元组：客户属性关系
```

### 查询示例

**安全查询**
```sql
-- 设置命名空间上下文
USE NAMESPACE tenant_123;

-- 查询自动应用命名空间隔离
SELECT * FROM customers 
WHERE status = 'active'
  AND created_at > '2026-01-01';

-- 无法泄露其他租户数据（数据库级别隔离）
```

**跨模态查询**
```sql
-- 客户360度视图
SELECT c.name, c.company,
       graph.neighbors(c, 'WORKS_WITH') as colleagues,
       vector.similarity(c.profile_embedding, :ideal_profile) as match_score,
       ts.activity_timeline(c.id, '30d') as recent_activity
FROM customers c
WHERE c.status = 'active'
ORDER BY match_score DESC
LIMIT 20;

延迟：<5ms
```
