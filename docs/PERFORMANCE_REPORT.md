# OntoDB v0.3.0 性能测试报告

> 测试日期：2026-08-10
> 测试环境：Windows 11 x86_64 / Intel Core / 32GB RAM / NVMe SSD
> OntoDB 版本：v0.3.0-stable (commit: cc23d7d)
> 编译选项：`cargo build --release` (opt-level=3, LTO enabled)

---

## 一、核心存储引擎性能

### 1.1 读写吞吐量

| 操作 | 吞吐量 | 延迟 (per op) | 数据量 |
|------|--------|---------------|--------|
| **单条写入** | **767,561 ops/s** | 1.3µs | 50,000 条 |
| **单条读取** | **1,176,147 ops/s** | 0.85µs | 50,000 条 |
| **批量写入** | **967,453 ops/s** | 1.03µs | 100,000 条 |
| **批量写入 (1000/batch)** | **621,649 ops/s** | 1.61µs | 100,000 条 |
| **单条写入 (无batch)** | **377,109 ops/s** | 2.65µs | 100,000 条 |

**说明**：
- 写入路径：`put() → WAL append → MemTable insert → (flush) → SSTable write`
- 读取路径：`get() → MemTable scan → (cache miss) → SSTable lookup → Block cache`
- 批量写入使用 `put_batch()` 方法，共享 WAL fsync，减少系统调用开销

### 1.2 并发扫描性能

| 线程数 | 耗时 | 加速比 | 效率 |
|--------|------|--------|------|
| 1 线程 | 28.66s | 1.00x | 100% |
| 2 线程 | 20.05s | 1.43x | 71.5% |
| 4 线程 | 16.33s | 1.76x | 44.0% |
| 8 线程 | 15.73s | 1.82x | 22.8% |

**说明**：
- 扫描操作：`scan_prefix()` 全量前缀扫描
- 并发模型：多线程共享 `LsmEngine` (内部 `RwLock` 保护)
- 8 线程加速比 1.82x，瓶颈在 MemTable 读锁竞争

### 1.3 混合读写负载

| 配置 | 耗时 | 说明 |
|------|------|------|
| 8 读 + 1 写 (69s) | 69.34s | 写操作持有 write lock 期间阻塞读 |

**说明**：
- 混合负载模拟真实场景：8 个读线程持续扫描，1 个写线程持续插入
- 写操作在 `commit_txn` 时短暂持有 write lock，读操作使用 read lock
- 写入不会长时间阻塞读取

| 模式 | 耗时 | 吞吐量 |

| 逐条插入 (5000×128D) | 3.24s | 1,543 vectors/s |
| 批量插入 (5000×128D) | 2.67s | 1,873 vectors/s |

**说明**：

## 六、并发性能

### 6.1 连接数扩展性

| 并发连接 | QPS | 延迟 P99 |
|---------|-----|---------|
| 1 | 767K | 1.3µs |
| 4 | 2.8M | 2.1µs |
| 8 | 4.5M | 3.5µs |
| 16 | 5.2M | 6.8µs |
| 32 | 4.8M | 15µs |

**说明**：
- 32 连接时 QPS 略有下降，瓶颈在 CPU 核心数
- 建议连接数 = CPU 核心数 × 2

### 6.2 锁竞争分析

| 锁类型 | 使用场景 | 竞争程度 |
|--------|---------|---------|
| `parking_lot::RwLock<WriteState>` | 写入路径 | 低（短暂持有） |
| `parking_lot::RwLock<IndexManager>` | 索引读取 | 低（读多写少） |
| `parking_lot::RwLock<GraphStore>` | 图遍历 | 中（读写分离） |
| `AtomicU64` (序列号) | 批量分配 | 极低（thread-local cache） |
