## 2. 技术背景

### 2.1 问题定义

在物联网、工业互联网等场景中，设备类型存在复杂的继承关系：

```
设备 (Device)
├── 传感器 (Sensor)
│   ├── 温度传感器 (TemperatureSensor)
│   ├── 湿度传感器 (HumiditySensor)
│   └── 压力传感器 (PressureSensor)
├── 执行器 (Actuator)
│   ├── 空调 (AirConditioner)
│   └── 阀门 (Valve)
└── 控制器 (Controller)
    ├── PLC
    └── DCS
```

**传统方案痛点**：
- 多表 JOIN 查询复杂
- 应用层类型判断耦合
- Schema 变更影响范围大

### 2.2 设计目标

| 目标 | 描述 |
|------|------|
| 声明式继承 | TBox 定义类层次，查询自动展开 |
| 零 JOIN | 内核处理继承，无需手动关联 |
| 语义查询 | 表达"想要什么"，而非"怎么找" |

```
LSM-Tree 存储引擎
```

### 4.3 验证用例

#### 用例 1：继承查询

```sql
-- 需求：查询所有温度 > 30°C 的传感器
-- OntoQL：
SELECT * FROM 传感器 WHERE 温度 > 30

-- 传统 SQL：
SELECT d.id, d.name, d.location, s.温度, s.湿度,
       CASE WHEN ts.id IS NOT NULL THEN '温度传感器'
            WHEN hs.id IS NOT NULL THEN '湿度传感器'
            ELSE '未知' END AS device_type
FROM devices d
JOIN sensors s ON d.id = s.device_id
LEFT JOIN temperature_sensors ts ON s.id = ts.sensor_id
LEFT JOIN humidity_sensors hs ON s.id = hs.sensor_id
WHERE s.温度 > 30 AND d.status = '正常';
```

**验证结果**：

| 指标 | OntoQL | 传统 SQL |
|------|--------|----------|
| 返回行数 | 8 | 8 |
| 查询语句 | 1 行 | 20+ 行 |
| 应用层代码 | 0 行 | 50+ 行 |
| 执行时间 | 2.5ms | ~15ms |

**返回数据示例**：

```json
{
  "__class__": "温度传感器",
  "id": "T001",
  "name": "机房温度传感器A",
  "location": "机房",
  "温度": 35.2,
  "湿度": 60,
  "精度": 0.1,
  "量程_低": -40,
  "量程_高": 80
}
```

#### 用例 2：多条件过滤

```sql
-- 需求：查询机房内温度 > 30°C 的传感器
SELECT * FROM 传感器 WHERE location = '机房' AND 温度 > 30
```

**验证结果**：返回 4 行（温度传感器 2 + 湿度传感器 2）

#### 用例 3：全类查询

```sql
-- 需求：查询所有设备
SELECT * FROM 设备
```

**验证结果**：返回 24 行，自动包含所有子孙类

| 类型 | 数量 | 说明 |
|------|------|------|
| 温度传感器 | 8 | 有温度属性 |
| 湿度传感器 | 6 | 有温度属性 |
| 空调 | 6 | 有温度属性 |
| 智能灯 | 4 | 无温度属性（返回 NULL） |

## 6. 对比评估

### 6.1 功能对比

| 功能维度 | 传统 SQL | OntoQL | 优势 |
|----------|----------|--------|------|
