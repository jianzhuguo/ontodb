# 从传感器到云端：边缘三级部署架构

> 物联网场景需要从微型控制器到云端的完整数据管理方案。OntoDB支持三级部署架构，共享统一数据模型，实现"一次开发，全场景部署"。

## 物联网部署的挑战

### 设备多样性

| 设备类型 | 内存 | 存储 | 网络 | 典型场景 |
|----------|------|------|------|----------|
| 微型控制器 | <1MB | <10MB | 低功耗 | 传感器节点 |
| 嵌入式设备 | 1-4GB | 16-64GB | WiFi/4G | 工业网关 |
| 边缘服务器 | 16-64GB | 1TB+ | 有线网络 | 边缘数据中心 |
| 云端服务器 | 128GB+ | 10TB+ | 专线 | 云数据中心 |

### 传统方案的问题

```
问题1：设备碎片化
- 微型控制器：SQLite（功能有限）
- 嵌入式设备：LevelDB（无语义推理）
- 边缘服务器：PostgreSQL（资源占用大）
- 云端：分布式数据库（架构复杂）

问题2：数据同步困难
- 不同数据库有不同的数据格式
- 同步需要定制开发
- 一致性难以保证

问题3：开发成本高
- 每种设备需要不同的代码
- 维护成本倍增
- 功能不一致
```

### 三级部署详解

#### 第一级：微型控制器部署

```
技术特点：
- no_std设计，不依赖标准库
- 编译裁剪，仅保留核心功能
- 引擎体积 < 100KB
- 内存占用 < 100KB

适用设备：
- ESP32、STM32、NRF52
- 传感器节点、可穿戴设备

功能：
- 数据采集和缓存
- 本地查询（简单条件）
- 离线运行
- 自动上报到边缘网关
```

#### 第二级：嵌入式Linux部署

```
技术特点：
- 完整数据库引擎
- 引擎体积 ~11MB
- 完整存储、查询、推理功能

适用设备：
- Raspberry Pi
- 工业网关
- 边缘服务器

功能：
- 本地数据存储
- 完整查询能力
- 本体推理
- 数据聚合和预处理
- 与云端同步
```

#### 第三级：边缘服务器/云端部署

```
技术特点：
- 与云端相同功能
- 支持多租户
- 支持集群部署

适用场景：
- 边缘数据中心
- 私有化部署
- 公有云部署

功能：
- 完整六模态存储
- 完整推理能力
- 分布式集群
- 多租户隔离
- API网关
```

```

- 压缩传输：减少带宽占用
- 断点续传：网络中断后自动恢复

同步流程：
1. 微型控制器 → 边缘网关（低功耗协议）
2. 边缘网关 → 边缘服务器（WiFi/4G）
3. 边缘服务器 → 云端（专线/VPN）
```

### 内存优化

```rust
// 微型控制器内存优化
#[cfg(not(feature = "std"))]
mod minimal {
    // 使用固定大小的缓冲区
    const BUFFER_SIZE: usize = 4096;
    static mut BUFFER: [u8; BUFFER_SIZE] = [0; BUFFER_SIZE];
    
    // 简化的存储引擎
    pub struct MinimalEngine {
        buffer: &'static mut [u8],
        offset: usize,
    }
    
    impl MinimalEngine {
        pub fn put(&mut self, key: &[u8], value: &[u8]) {
            // 直接写入缓冲区
            let entry = Entry::new(key, value);
            let bytes = entry.to_bytes();
            self.buffer[self.offset..self.offset + bytes.len()].copy_from_slice(&bytes);
            self.offset += bytes.len();
        }
    }
}
```

### 数据同步协议

```rust
// 增量同步协议
struct SyncProtocol {
    last_sync_id: u64,
    batch_size: usize,
}

impl SyncProtocol {
    // 增量同步
    async fn sync_incremental(&mut self, remote: &mut RemoteEngine) -> Result<()> {
        let changes = self.get_changes_since(self.last_sync_id);
        
        for batch in changes.chunks(self.batch_size) {
            // 压缩数据
            let compressed = compress(batch);
            
            // 传输数据
            remote.apply_changes(compressed).await?;
            
            // 更新同步点
            self.last_sync_id = batch.last().unwrap().id;
        }
        
        Ok(())
    }
    
    // 断点续传
    async fn sync_with_resume(&mut self, remote: &mut RemoteEngine) -> Result<()> {
        loop {
            match self.sync_incremental(remote).await {
                Ok(()) => break,
                Err(Error::NetworkTimeout) => {
                    // 网络超时，等待重试
                    tokio::time::sleep(Duration::from_secs(5)).await;
                    continue;
                }
                Err(e) => return Err(e),
            }
        }
        Ok(())
    }
}
```
